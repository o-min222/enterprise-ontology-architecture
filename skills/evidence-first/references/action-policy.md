# 판단과 실행 권한 분리

`verified`는 확인 범위를 나타내며 실행 허가가 아니다. 공식 결정도 그 자체로 현재 AI 계정의 API 쓰기 권한이나 배포 승인을 제공하지 않는다. 스킬 설치는 인증·권한 부여가 아니다.

| 작업 | 확인·보존할 것 |
| --- | --- |
| 읽기·분석·제안 | 허용된 접근 범위, 출처·불확실성. 실행 권한 없이도 수행 가능 |
| 독립 평가 작성·공유 | 작성자·목적·기준·공유 대상. 공통 사실에 자동 반영 금지 |
| L1 원천 정정 | 원천 오너의 권한, 증빙, 이전 값·정정 사유·이력 |
| L2 의미 정의 변경 | 모델 오너·영향 부서, 영향 분석·버전·복구 |
| 공식 판단 채택 | 업무 권한자, 결정 기준·적용 기간·철회 조건 |
| 실제 업무 실행 | 대상 시스템·객체·작업·권한·필수 승인·영향·감사·복구 |

## 실행 전후

실행 전 요청의 대상·환경·변경 내용과 사용자가 허용한 범위를 대조한다. 사용자의 기존 승인을 활용하며 모든 파일 수정에 새 승인을 요구하지 않는다. 조직 정책이 요구하는 별도 승인과 서비스 권한이 있는지 확인한다. 권한이 없거나 불명확하면 해당 실행을 보류하고 구체적인 변경안·영향·검증·복구 방법을 준비한다.

읽기 전용 토큰을 쓰기 토큰으로 바꾸거나 서비스의 승인 장치를 우회하지 않는다. 조회·분석 도구와 쓰기 도구·자격증명을 분리하고 서버/API/DB가 역할·대상·승인 범위를 검증하게 한다. 높은 영향의 실행에는 서비스 측 승인·감사·복구 통제를 적용한다. 이는 통합 시스템이 구현할 책임이며 Markdown이 강제하지 못한다.

실행 후 응답과 실제 상태를 확인한다. 요청 ID·대상·시각·관측된 결과·검증 범위·남은 불확실성을 권한 있는 감사 기록에 남긴다. “실행 예정”, “요청 접수”, “완료 확인”을 구분한다. API가 작업을 접수한 것만 확인했다면 완료라고 보고하지 않는다.

타임아웃·연결 끊김은 실행 여부 불명이다. 상태 조회·요청 ID·멱등 키로 중복 여부를 확인한 뒤 필요하고 허용된 경우만 재시도한다. 제한 없이 재시도하지 않는다. 상태가 불명확하거나 영향이 확대되면 중단하고 이를 보고한다. 실패한 실행도 관측 가능한 실패 결과로 기록할 수 있지만 미실행 계획을 `execution_result`로 기록하지 않는다.
