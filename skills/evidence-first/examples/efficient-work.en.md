# Synthetic efficiency choices

These are fictional situations, not measured operational improvements. Follow [efficient work](../references/efficient-work.en.md).

For one question over five accessible records, use existing files/original references when sufficient. No new graph/RAG/benchmark/permanent learning file is needed.

For an authorized recurring-query comparison, fix source/definition versions, representative questions and failure cases, then compare current behavior with one promising local alternative in an authorized copy. Check equivalent evidence/type/status/scope first and separate setup/indexing, query, review, and maintenance burden.

A faster query with expensive setup or unknown reuse is not proof of lower overall burden. Small/uncertain differences can justify retaining the current environment. Omitting citations or uncertainty to be faster fails the quality floor. Do not invent token, cost, or accuracy savings.

Reuse a retained method only when task, source/definition, quality, tools, and permission still match. Do not repeat the same experiment without reason, treat experience as universal truth, or widen authority. Revisit after material conditions change; retain failed/uncertain results too.
