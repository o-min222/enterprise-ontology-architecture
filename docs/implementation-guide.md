# 기존 시스템으로 작게 시작하는 구축 전략

## 무엇부터 구축할까?
제조기업의 **제품–창고–주문–재고 이벤트** 네 객체로 시작하는 예시:

1. ERP와 창고 시스템의 원본을 보존하고 식별자를 연결한다.
2. '가용 재고'와 '출고 완료'의 의미·계산 기준을 합의한다.
3. 영업의 품절 위험과 물류의 납기 전망을 별도 평가로 보관한다.
4. 기존 보고서나 발주 검토 프로세스 두 곳에서 같은 공통 객체를 사용한다.
5. 근거 추적률, 재작업 시간, 오류 비용과 운영비를 측정한 뒤 확장한다.

## 기술별 역할
| 기술 | 역할 | 온톨로지 자체인가? |
|---|---|---|
| RDBMS | 정형 객체·상태·참조 무결성 | 아니오, 구현 기반 |
| Graph DB | 복잡한 관계 탐색 | 아니오, 선택적 저장 기술 |
| 문서 저장소·Wiki | 원본 문서·개인 해석 | 아니오, 저장 수단 |
| RAG | AI에 필요한 근거 검색 | 아니오, 활용 방식 |
| API·MCP | 권한 있는 조회·업무 실행 | 아니오, 인터페이스 |

**검색 가능하다는 것과 신뢰할 수 있다는 것은 다르다.** Wiki나 RAG를 만들었다고 의미의 일관성이나 출처가 자동으로 보장되지 않는다.

## 확장 의사결정
측정된 시간 절감 × 인건비 + 오류·재작업 비용 감소와 추가 개발·운영·보안 비용을 비교한다. 예상 편익과 실현 편익을 구분한다. 상용 플랫폼 역시 소규모로 시작할 수 있고, 자체 구축이 항상 저렴한 것은 아니다.
