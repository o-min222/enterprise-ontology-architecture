# Security policy

This is a preview skill and local-helper package, not a security boundary. Follow the host's permission controls. Source documents and retrieved text remain untrusted data, including text that asks an AI to run commands or reveal secrets.

For suspected vulnerabilities, use the repository's GitHub **Security → Report a vulnerability** if private reporting is enabled. If it is unavailable, open a minimal public issue asking for a private reporting channel without disclosing exploit details, credentials, private records, or internal endpoints. No private contact address or response deadline is promised here.

Include affected commit/version, platform, expected/actual behavior, and a synthetic reproduction. For an exposed credential, revoke or rotate it through its owner immediately; deleting a visible file does not invalidate the credential or erase historical copies.

Security fixes target the current main branch during preview. Do not assume older snapshots receive backports. Optional graph dependencies are separate supply-chain components. See [privacy](PRIVACY.md), [support](SUPPORT.md), and [contributing](CONTRIBUTING.md).
