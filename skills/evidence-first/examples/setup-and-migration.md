# 가상 예제: 선택하고 나중에 바꾸기

모든 데이터·경로는 **가상**이다. 실제 실행은 사용자가 지정한 작업 폴더와 권한 안에서 수행한다. [초기 설정·전환 절차](../references/workspace-lifecycle.md)의 보조 도구를 사용할 수 있다.

## 처음에는 행동만

사용자: “이 폴더에는 Evidence-First 행동 원칙만 적용해줘.”

AI: 기존 선택이 없으면 `init --mode behavior`로 로컬 설정을 남긴다. Wiki나 DB는 생성하지 않는다. 이후 분석에서는 공통 근거와 정의를 확인하지만 매 응답을 저장하지 않는다. 사용자가 설정 파일도 원하지 않으면 파일 없이 원칙만 적용한다.

## Wiki 없이 DB부터 추가

사용자: “반복 조회할 기록이 생겼으니 로컬 DB를 추가해줘.”

AI: 기존 행동 설정을 유지하며 `add db`로 SQLite를 생성한다. `enabled_components`는 `["db"]`, `primary_store`는 `db`다. Wiki를 중간 단계로 만들지 않는다. 기존 대화 내용을 동의 없이 전부 수집하거나 검증된 데이터로 등록하지 않는다.

## Wiki를 나중에 추가하거나 기준을 이전

사용자: “사람이 읽기 쉽게 Wiki도 추가해줘. DB는 계속 기준으로 쓸게.”

AI: `add wiki`로 구성만 추가한다. 기준은 DB 그대로다. 추가만 했으므로 Wiki에 기존 DB 데이터가 복사됐다고 말하지 않는다. 읽기용 페이지가 필요하면 범위를 정해 DB로부터 생성하며 시점과 기준 출처를 표시한다.

사용자: “이제 기록의 기준을 Wiki로 옮겨줘. DB는 남겨둬.”

AI: `migrate --to wiki`로 계획을 확인하고, 기존 승인 범위 안에서 `migrate --to wiki --apply`를 실행한다. 원본·대상 전체 레코드 값과 건수를 대조한다. 복사 중 출처·L2 버전·유형·검증 상태를 변경하지 않는다. 성공 후 기준은 Wiki이며 DB와 `shared/`의 원천·정의·독립 해석은 남는다. 이후 Wiki 수정이 DB에 자동 반영되는 것은 아니다.

## 같은 모양의 다른 데이터가 있는 경우

사용자: “Wiki에 다른 평가도 있는데 DB 데이터로 바로 덮어써.”

AI: 두 기록 집합의 차이·작성자·출처·버전을 비교하고 충돌 매핑을 준비한다. 동일 ID의 다른 평가를 하나의 사실로 합치지 않는다. 기본 보조 도구는 서로 다른 대상을 덮어쓰지 않는다. 기존 Wiki 자료의 별도 보관과 병합/이전 범위를 정한 후 진행한다.

## 기존 회사 DB를 쓰는 경우

사용자: “우리 PostgreSQL에 연결해줘.”

AI: 기존 스키마·접근 권한·원천 참조를 먼저 조사한다. SQLite를 대신 생성하지 않는다. 연결 참조·DDL·컬럼 매핑·테스트·복구 계획을 작성하고 필요한 권한이 있는 범위에서 적용한다. 이 요청을 로컬 보조 도구의 DB 옵션만으로 완료했다고 보고하지 않는다.

## 그래프 DB와 RAG를 나중에 추가

사용자: “기존 Wiki를 보존하고 그래프 DB로 이전해줘. 관계 탐색과 RAG도 사용하고 싶어.”

AI: [그래프·RAG 안내](../references/graph-and-rag.md)에 따라 선택 의존성을 대상 환경에 설치한다. Wiki의 가상 기록을 읽기 전용으로 조사하고 `migrate --to graph` 계획·대조 뒤 `--apply`로 이전한다. Wiki는 남고 기준은 그래프 DB로 바뀐다. `enable graph_traversal`, `enable rag`는 저장소 이전과 별도로 수행한다. `rag.py build`로 새 기준을 색인한다.

사용자: “냉각 원인이 확인됐나? 재가동 결정은 유효한가?”

AI: `rag.py retrieve`의 근거를 사용하고 필요한 원본을 별도로 확인한다. 예제에서는 냉각 원인은 `hypothesis/unverified`, 결정의 현재 효력은 `official_decision/disputed`이므로 이 상태를 답변에서 드러낸다. `E1` 등의 인용과 실제 원천 위치를 연결한다. 검색이나 그래프 연결 때문에 원인을 확정하거나 재가동을 실행하지 않는다.

사용자: “다시 SQLite를 기준으로 바꿔줘.”

AI: 기존 대상과 데이터를 대조한 뒤 기준을 이전하고, 기존 그래프 DB와 원천을 보존한다. RAG 기능은 유지하지만 기준 저장소가 바뀌었으므로 이전 색인의 조회는 거부된다. 새 기준에서 `build`를 수행한다.
