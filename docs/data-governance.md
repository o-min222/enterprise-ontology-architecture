# 데이터 거버넌스: 공유, 검증, 변경

## 원천 데이터도 선택된 현실의 표현
원본은 수정 이력을 보존하지만, 그 자체가 절대적 진실은 아니다. 수집 목적·대상·기간·방법·누락 가능성을 데이터셋 단위로 기록한다. 작성자·시각·원본 시스템·객체 ID는 가능한 자동 수집한다.

## 서로 다른 변경 경로
| 요청 | 책임 | 처리 결과 |
|---|---|---|
| 원천 사실 정정 | 원천 시스템 오너 | 증빙 대조, 이전 값과 정정 사유 보존 |
| 개인 평가 공유 | 작성자·업무 책임자 | 공유된 **평가**로 보존, 사실로 자동 승격 금지 |
| 공통 의미 정의 변경 | 데이터 오너·영향 부서 | 영향 분석, 버전 발행, 롤백 |
| 공식 판단 채택 | 업무 권한자 | 판단 기준·기간·철회 조건 기록 |
| 실제 업무 Action | 권한자 또는 승인 규칙 | 감사 로그·취소/보상 조치 |

SLA는 중요도에 따라 달라진다. 긴급 장애 정정과 일반적인 정의 변경을 동일한 절차로 취급하지 않는다.

## 비례적 관리
- **핵심:** 재무·규제·개인정보·전사 핵심 데이터 → 출처·정의·승인·감사 필수.
- **표준:** 반복 재사용 데이터 → 자동 메타데이터와 정기 점검.
- **경량:** 낮은 영향의 일회성 자료 → 최소 ID·출처·시각.

## 신뢰성 측정
- 근거 추적률 = 유효한 원본 링크를 가진 점검 항목 / 전체 점검 항목
- 의미 충돌률 = 발견된 정의 충돌 / 검토한 정의
- 사실·평가 혼동 건수
- 월 유지관리 인시와 총소유비용(TCO)

개인 의견의 공유와 공식 사실의 정정은 반드시 구분한다.
