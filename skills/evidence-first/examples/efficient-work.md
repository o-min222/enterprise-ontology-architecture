# 가상 예제: 더 효율적인 방향 찾기

이 문서의 상황은 **가상**이다. 측정값이나 운영 개선을 실제로 입증한 사례가 아니다. [효율 비교와 학습](../references/efficient-work.md)에 따라 실제 근거를 확보한다.

## 작은 단발성 질의

사용자: “자료 다섯 건에서 냉각 원인이 확인됐는지 한 번만 알려줘.”

AI는 기존 파일·원천 참조로 답할 수 있는지 먼저 확인한다. 충분하면 가설·미확인 상태와 출처를 유지해 답하고 마친다. 이 요청만으로 새 그래프 DB·RAG·벤치마크·영구 경험 파일을 생성하지 않는다.

## 반복 업무의 작은 비교

사용자: “이 질문들이 반복되니 현재 방법보다 나은 방향을 찾아줘. 로컬 실험 사본에서 후보 하나를 비교해도 돼.”

AI는 원본/설정 버전과 대표 질문·중요한 실패 사례를 정하고 기존 방법을 확인한다. 기존 검색 질의 개선 또는 RAG 같은 유망한 후보 하나를 허용된 실험 사본에서 비교할 수 있다. 같은 질문에 필요한 근거·유형·검증 범위가 유지되는지 먼저 확인하고 설정/색인·질의·검토·갱신 부담을 구분한다.

후보가 질의 한 번은 빨라도 색인·유지 부담이 크고 반복 사용량이 불확실하면 그 한계를 밝힌다. 비교 차이가 작거나 현재 방식으로 충분하면 환경을 유지한다. 후보를 설치했다는 사실만으로 효율 개선을 주장하지 않는다.

## 빨라졌지만 출처를 잃은 경우

후보가 원본 링크·검증 상태를 빼서 응답을 짧게 만들었다면 품질 조건을 충족하지 못한 방법이다. 속도 이점으로 이를 정당화하지 않고 출처·불확실성을 유지하는 대안을 찾는다. 실제 측정하지 않은 토큰·금액·정확도를 절감 실적으로 보고하지 않는다.

## 같은 조건에서 재사용

유효한 비교 결과가 있고 다음 요청의 업무·자료/정의 버전·품질·권한 조건이 같으면 그 경험을 읽고 선택한 방법을 우선 사용한다. 매번 같은 실험을 반복하지 않는다. 원천 버전·질문 종류·규모·모델/도구가 달라지면 적용 가능성을 다시 확인한다.

경험은 이 프로젝트의 조건부 방법 선택 근거다. 모든 조직의 공통 사실로 반영하거나 권한 정책을 확대하는 근거로 사용하지 않는다. 실패·효과 미확인 결과도 남겨 같은 근거로 반복 도입하지 않는다.
