# 온톨로지의 정의와 범위

## 전통적 정의
지식공학에서 온톨로지는 개념화의 명시적 명세(Gruber, 1993)로 설명된다. OWL은 클래스·속성·개체·논리적 공리를 통해 개념과 관계를 표현한다.

## 이 프로젝트의 작업 정의
- **협의의 온톨로지(L2):** 기업의 공통 객체, 속성, 관계, 의미, 제약.
- **광의의 운영형 온톨로지:** L2 모델을 실제 상태와 권한·업무 Action에 연결한 운영 체계.
- **L1 원천 데이터:** 원천 기록, 문서, 로그 등. 단순 재료가 아니라 권한에 따라 재사용할 **공유 자산**.
- **L3 활용:** 업무 앱, BI, API, AI 에이전트 등. AI는 온톨로지의 필수 구성요소가 아니다.

이 구분은 이 제안서의 작업 정의이며 학계의 단일한 표준 정의가 아니다.

## 왜 완전한 중립성보다 추적 가능성인가
현실을 기록할 때 무엇을 관측하고 누락할지 선택한다. 공통 모델을 만들 때도 어떤 객체와 관계를 중요하게 볼지 결정한다. 따라서 목표는 편향의 부재를 선언하는 것이 아니라 **선택의 맥락을 기록하고 다른 사람이 독립적으로 검증·재해석할 수 있게 하는 것**이다.
