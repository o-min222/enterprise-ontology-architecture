## 수행하지 않은 검증

이 기록은 모든 시나리오의 자동 모델 평가나 여러 제품의 실제 세션 검증을 뜻하지 않는다. Codex·Claude Code 앱에서 스킬 목록/명시 호출을 각각 확인하는 과정, macOS/Linux 설치 명령 실행, 실제 L1/L2 서비스·DB 권한·승인·복구 검증은 수행하지 않았다. 이는 [설치 안내](../docs/evidence-first-installation.md)와 [행동 시나리오](scenarios.md)로 후속 확인할 수 있다.

JSON Schema는 구조를 검사한다. 검증 근거의 진위, 모델 응답의 신뢰성, 서버 측 접근 통제는 별도 검증 대상이다. 스키마의 `date-time` format은 검증기 설정에 따라 annotation으로만 취급될 수 있다. 이번 테스트는 예제 `created_at`의 시간대 포함 여부도 별도로 확인했다.

## 그래프 DB·RAG 확장 검증

확장 기준 커밋: `09490523b82cca3b240d8000c9c4cfc716b71a22`. 위 기록은 각 이전 버전의 검증 범위를 보존한 것이다. 현재 버전은 아래와 같이 로컬 Oxigraph와 키워드 RAG를 추가했다. 검증일은 위와 동일하다.

- 자동 테스트 총 **36개 통과**. 실제 Oxigraph DB 생성·SPARQL 조회·Wiki↔그래프↔SQLite 왕복 이전·모든 JSON 값 보존, 그래프의 20개 정보 유형/검증 상태 조합, 미등록 triple·다른 투영의 거부를 확인했다.
- Wiki·관계형 DB·그래프 DB의 7개 비어 있지 않은 저장 조합과 별도의 RAG 기능 선택을 검사했다. v1 설정은 조회·이전 계획에서 바이트가 유지되며, 기능 추가 시 v1 사본을 남기고 v2로 전환되는 것을 확인했다.
- 세 기준 저장소 각각에서 실제 FTS5 검색을 수행했다. 한국어 질의, 출처·검증 범위를 포함한 전체 payload 보존, 빈 결과, 질문 구문 처리, 기준/레코드 변경 시 색인 거부, 원본과 달라진 색인 payload의 거부, 재색인 실패 시 기존 색인 보존을 확인했다. 설치 스킬만 복사한 상태에서 외부 패키지 없이 로컬 RAG를 실행했고 그래프 선택 의존성의 분리도 확인했다.
- 실제 검사 환경: Python 3.14.4, SQLite 3.50.4, pyoxigraph 0.5.13, jsonschema 4.26.0, PyYAML 6.0.3. 그래프 의존성은 격리된 개발용 환경에 설치했다. `quick_validate.py`와 diff 공백 검사도 통과했다.

독립 평가 에이전트는 스킬의 기대 답안·테스트를 읽지 않고 새 설치 사본과 격리 폴더에서 다음 흐름을 실제 수행했다:

1. Wiki의 가상 레코드 5건과 원천 파일을 검증해 등록한 뒤 그래프 DB를 추가·이전했다. 기존 Wiki와 원천 바이트가 유지됐고 전체 JSON의 digest는 `b4eba2546aab8c6236bf3c54134f57069fbc087b5d0fb27014ea8c25e1b7a084`로 같았다.
2. 실제 RDF quad 32개와 `about` 5개·`derivedFrom` 6개·`usesModel` 1개를 확인했다. 객체 관계 조회에는 5건과 `is_primary: true`가 반환됐다.
3. RAG를 별도로 활성화·색인·검색한 뒤 코딩 AI가 실제 한국어 답변을 생성했다. “냉각 원인은 확인됐나? 재가동 결정은 지금 유효한가?”에 `HYP-DEMO-1/hypothesis/unverified`와 `DECISION-DEMO-1/official_decision/disputed`를 구분했다. 실제 가상 원문도 별도로 읽었으며 인용 ID와 원천 앵커를 연결했다. 결정 존재와 안전성의 증명을 혼동하거나 재가동을 실행하지 않았다.
4. 기준을 Wiki로 다시 이전했다. 데이터 digest가 같아도 그래프 기준의 이전 색인은 `RAG index is stale or from another store; rebuild it`로 거부됐고 색인 파일은 변경되지 않았다. Wiki 기준 재색인 뒤 검색이 재개됐으며 그래프 조회는 `is_primary: false`가 됐다.

기능 결함은 이 독립 시험 범위에서 발견되지 않았다. 결합 질문에서 관련 없는 타임아웃 기록도 검색돼, 답변에는 관련 있는 두 항목만 사용했다. 로컬 검색의 정밀도 한계와 관련성 판단 절차를 안내에 명시했다.

현재 지원 범위는 로컬 RDF DB와 키워드 RAG 검색·컨텍스트·호출 AI의 생성이다. 원격 그래프 서버, 임베딩/벡터 검색, 범용 다단계 GraphRAG 추론, 외부 모델 API·예약 생성·사용자별 ACL 서비스는 이번에 구현·검증하지 않았다. 실제 Codex/Claude Code 제품의 자동 발견·호출 시험과 다중 앱 동시 쓰기 검증도 이전과 같이 별도 범위다. 기존 아키텍처 문서 6개와 구축 프롬프트 4개는 보존했다.

독립 평가 에이전트는 기대 답안·테스트를 읽지 않고 새 스킬 사본과 세 개의 격리된 가상 프로젝트에서 실제 작업을 수행했다. 준비 이후 사본과 파일 바이트를 비교했다.

모든 사례의 기준 레코드·가상 원천·기존 정책은 준비 후 사본과 바이트가 같았다. 새 저장소·외부 의존성·원격 전송·서비스 호출은 추가하지 않았다. 검색 결과와 생성 답변은 가설을 `hypothesis/unverified`로 유지했다.

독립 평가에서 명확한 지침 모순이나 기능 결함은 발견되지 않았다. B의 RAG 질의가 유지보수까지 암묵적으로 포함하는지 해석 여지는 있었으나 저장된 제안 전용 정책을 따르고, 사용한 근거 조회 방식과 미실행 상태를 밝혔다.

자율 정책은 AI가 읽고 따르는 선호·허용 범위 기록이다. 새 실행 엔진·상시 감시·스케줄러·정책 강제 장치는 추가하지 않았다. 정책 소유자의 실제 승인 근거, 현재 요청 범위, 서비스·OS의 권한과 업무 효과는 별도 판단·검증 대상이다. 기존 아키텍처 문서 6개와 구축 프롬프트 4개는 이번에도 보존했다.

## 효율 탐색·조건부 경험 재사용 검증

확장 기준 커밋: `4697c133d4895f877aa2d7e47ee245d8bfd1d623`. 검증일은 위와 동일하다. 효율 탐색은 AI의 목적·품질 조건 확인, 작은 비교, 전체 부담 평가, 조건부 로컬 경험 재사용 규칙으로 구현했다. 실행 엔진·새 의존성·권한 모드는 추가하지 않았으며 기존 구성·RAG 도구를 활용한다.

기존 자동 테스트 **39개 통과**, `quick_validate.py`, 스킬 단독 복사·참고 경로 및 diff 공백 검사를 확인했다. 자동 검사는 기존 기능과 패키지의 회귀 범위다. 실제 판단은 기대 답안·테스트를 읽지 않은 별도 에이전트가 새 설치 사본과 격리된 가상 자료로 평가했다.

- **단발성 요청:** Wiki 가상 기록 5건에서 냉각 원인이 확인됐는지 질문했다. AI는 필요한 기록·원문을 읽고 `hypothesis/unverified`와 원천 인용으로 답했다. 벤치마크·새 구성·영구 기록을 만들지 않았고 원본의 모든 파일 바이트가 유지됐다.
- **반복 질의의 작은 비교:** 원본을 바꾸지 않는 별도 실험 사본에서 현재 직접 조회와 로컬 FTS5/BM25 RAG 하나를 대표 질의 4개에 각 1회 비교했다. 자동 로컬 실행 전체는 0.138초로, 지정된 30초 제한 안이었다. 사본 준비 22.75ms, RAG 활성화·색인 42.63ms와 질의별 시간을 분리해 기록했다. 이 표본에서는 RAG의 전체 부담상 이점을 확인하지 못해 직접 조회를 유지했다.
- **품질 조건:** 냉각 원인의 미확인, 기록상 정지 40분과 Wiki 20분의 충돌, 결정의 현재 효력 `disputed`, 타임아웃 후 작업 생성 미확인을 보존했다. 두 방법에서 원문을 별도로 읽고 검색 payload의 전체 값·출처·버전·검증 범위 불변을 확인했다. 관련 없는 검색 항목을 답변에서 제외했다.
- **후속 재사용:** 실험 폴더에 관측·한계·적용 조건을 기록했다. 후속 요청에서 자료 digest·원문/도구 해시·Python·권한·품질 조건이 같은지 확인하고 직접 조회 경험을 재사용했다. 비교 실험을 반복하지 않았으며 원본의 모든 파일 바이트와 기존 설정이 유지됐다.

측정은 같은 Python 프로세스에서 각 방법을 질의별 한 번 실행한 탐색 결과다. 직접 조회 시간은 1.26~2.52ms, RAG 질의는 첫 질의 50.78ms와 나머지 3.21~3.66ms였다. Python 시작·모듈 로딩·AI 검토/생성 시간·장기 유지 비용은 포함하지 않았다. 한 번의 작은 표본에서 보편적 성능 순위, 모델 토큰/금액 절감, 정확도 개선률, 운영 전체 개선을 주장하지 않는다.

독립 평가 범위에서 지침 모순이나 기능 결함은 발견되지 않았다. 경험 기록은 조건부 작업 근거이며 모델 가중치 학습·공통 원천 사실·추가 실행 권한이 아니다. 기존 아키텍처 문서 6개와 구축 프롬프트 4개는 보존했다.

## 다국어 확장 검증

확장 기준 커밋: `48709dd06f0e5c0a2e4c2d1e3cba26a795fd6e4d`. 검증일은 위와 동일하다. 표준 영어 진입점과 한국어 보존본, 한국어·영어 핵심 가이드, 일본어·중국어 빠른 시작, 확장 가능한 en/ko/ja/zh 카탈로그를 추가했다. 응답 언어는 사용자의 명시 요청·선호·대화를 따르며 원문·ID·열거형·권한은 변경하지 않는다.

자동 테스트 **47개 통과**: 기존 39개에 카탈로그·대체 언어·잘못된 태그/경로 거부·영어 예제 스키마/식별자/출처·다국어 Wiki 이전의 전체 값 보존·원래 질문과 별도 검색어·CJK 어절 검색·이전 색인 거부/재생성·독립 설치 UTF-8 CLI 검사 8개를 추가했다. 언어별 루트 문서·설치·프롬프트 링크와 동일 스킬 활성화 ID도 검사했다. `quick_validate.py`와 diff 공백 검사도 통과했다.

별도 평가 에이전트가 영어 지침과 원천만 읽고 새 설치 사본으로 SQLite→일본어 Wiki 이전, RAG 생성·질의를 실제 수행했다. 모든 JSON 값이 동일했고 일본어 레이블이 표시됐다. 일본어 질문은 영어 원천 검색어를 따로 사용해 원래 질문을 보존하고 일본어로 답했으며, 냉각 원인의 hypothesis/unverified와 출처를 유지했다.

카탈로그가 없는 스페인어는 도구 메시지 es→en 대체를 실제 표시했다. AI의 답변은 스페인어였고 현재 재가동 결정의 official_decision/disputed·검증 범위와 채택/보류 원문 인용을 유지했다. 필요한 원문을 별도로 읽었으며 무관한 검색 결과는 답변에 사용하지 않았다. 언어 전환 전후 config·색인·Wiki JSON·페이지·기존 DB·원천 파일 여섯 개가 모두 바이트 동일했고 언어만을 위한 재색인은 없었다.

이 범위에서 결함이나 지침 모순은 발견되지 않았다. 지원 범위는 AI 요청 언어 응답, 유지되는 영어/한국어 핵심 지침, 일본어/간체 중국어 빠른 시작과 네 도구 카탈로그다. 기술 CLI 진단은 영어이며 다른 유효한 언어 태그는 영어 메시지 대체를 표시한다. 모든 언어의 검토된 문서·번역 품질·의미 검색 성능을 보장하거나 외부 자동 번역을 구현했다고 주장하지 않는다. 색인 형식은 CJK 어절 검색용 버전 2로 갱신했으며 버전 1은 권한 범위에서 다시 만들어야 한다.
