# 검증 실행

스킬을 읽는 데 Python은 필요하지 않다. 다음 의존성은 개발용 검사에만 사용한다. 저장소 루트에서 Python 3.10 이상으로 실행한다.

선택적 로컬 설정/이전 보조 도구도 Python 3.10 이상에서 실행된다. Wiki·SQLite·로컬 키워드 RAG는 표준 라이브러리만 사용하고 그래프 DB에는 선택 의존성 pyoxigraph가 필요하다. 전체 테스트 의존성에는 실제 그래프 DB 검사도 포함한다.

```sh
python -m venv .venv
```

가상환경을 활성화한다: Windows PowerShell은 `.venv\Scripts\Activate.ps1`, macOS/Linux는 `source .venv/bin/activate`. 조직 정책상 활성화가 제한되면 가상환경의 Python 실행 파일을 직접 사용한다.

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
git diff --check
```

검사 범위: 표준 frontmatter, 패키지만 복사한 상태의 로컬 참고 경로, JSON Schema 유효성, 5×4 독립 조합, 잘못된 유형·상태, 검증 근거 누락, 가상 기록의 스키마 및 출처 연결. 단위 테스트의 조합 생성은 형식 검사이며 그 조합의 실제 진실성을 입증하지 않는다.

로컬 구성 검사는 기본 초기 선택, DB 직접 추가, 기준 저장소 유지, 부작용 없는 이전 계획, Wiki↔SQLite 전체 기록 대조, 공통 자료·원본 보존, 충돌·전환 실패·잘못된 기록·잠금·기존 저장소 보호, 독립된 SQLite CHECK 제약을 실제 임시 파일과 DB로 확인한다. 설치 폴더만 복사한 상태에서 외부 패키지 없이 Wiki·SQLite 보조 도구가 실행되는지도 검사한다.

그래프/RAG 검사는 세 저장소의 모든 조합, 저장·기능 축의 분리, v1 설정의 읽기 전용 호환과 변경 시 이력 보존, 실제 Oxigraph/SPARQL 조회·왕복 이전·알 수 없는 triple의 거부, 그래프의 20개 유형/상태 조합을 확인한다. Wiki·SQLite·Oxigraph 각각의 로컬 검색과 출처/검증 상태 보존, 빈 검색 결과, 잘못된 질문 구문, 색인 변경 감지·원본과 다른 색인 payload 거부·실패한 재색인의 이전 색인 보존도 검사한다. 생성 문장의 품질은 단위 테스트와 별도로 실제 AI 응답으로 평가한다.

환경 개선 정책 검사는 세 정책 모드와 예제 형식, 지정되지 않은 작업·포괄 허용·승인 참조 누락의 거부, 저장·기능 설정과 정책의 분리를 확인한다. 이는 정책 JSON의 계약 검사이며 CLI 권한 강제나 AI 판단의 정확성을 입증하지 않는다. 실제 제안·진행·보류는 별도 행동 평가로 확인한다.

효율 탐색은 실제 AI가 단발성 작업·작은 비교·품질 조건·경험 재사용을 처리하는 별도 행동 평가로 확인한다. 패키지 검사는 새 참고자료·양식의 설치 독립성을 점검하지만, 특정 방법이 언제나 빠르다는 성능 보증을 만들지 않는다. 작은 가상 자료의 실험 결과를 운영 환경 전체로 일반화하지 않는다.

[scenarios.md](scenarios.md)는 모델의 실제 판단과 도구 사용을 평가한다. 자동 테스트 통과가 모든 AI의 지침 준수·보안·접근 권한을 보장하지 않는다. 실제 제품별 호출과 모델 평가 결과는 제품·모델·버전·시각·실행 로그와 함께 따로 기록한다.

이번 구현에서 실제 실행한 검사와 미검증 범위는 [검증 기록](validation-report.md)에 정리했다.

기존 문서 보존 확인은 변경 전 커밋과 비교한다. 예를 들어 `git diff <기준-커밋> -- docs/ prompts/`에서 기존 파일 변경을 확인하고, 의도한 새 설치 안내 외의 수정이 없는지 검토한다.
