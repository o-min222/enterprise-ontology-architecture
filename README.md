# 기업 온톨로지의 신뢰성과 활용성을 높이기 위한 설계 원칙

기업의 원천 기록(L1)과 공통 의미 모델(L2)을 공유 자산으로 관리하고, 개인·부서·AI의 해석을 독립적으로 보존하는 아키텍처 및 데이터 거버넌스 제언입니다.

## 핵심 원칙

- **공유:** 원천 데이터와 공통 의미 모델은 권한 범위 안에서 공유합니다.
- **독립:** 해석과 평가는 공통 사실을 덮어쓰지 않습니다.
- **비례:** 중요도와 위험에 따라 관리 수준을 조정합니다.
- **추적 가능성:** 출처, 수집 맥락, 정의와 변경 이력을 확인합니다.

## 구축 접근

기존 관계형 DB와 API로 작은 객체 모델부터 시작할 수 있습니다. 그래프 DB, Wiki, RAG, MCP는 각각의 역할과 필요성을 확인한 뒤 선택합니다. AI는 온톨로지 자체가 아니라 외부 활용 수단입니다.

> 공개 저장소입니다. 기업 내부 자료, 개인정보, 비밀정보는 게시하지 않습니다.

## Evidence-First: 여러 코딩 AI를 위한 스킬

공유 L1·L2 활용, 해석 독립, 비례적 검증, 출처 추적에 **실행 권한 분리**를 더한 재사용 가능한 행동 지침입니다. AI는 온톨로지의 외부 활용자이며, 스킬은 실제 접근 통제나 승인 시스템을 대체하지 않습니다.

- [스킬 본문](skills/evidence-first/SKILL.md): 표준 `SKILL.md`, 도구에 종속되지 않는 공통 규칙.
- [설치 및 연동](docs/evidence-first-installation.md): Codex·Claude Code 설치, AGENTS.md·CLAUDE.md 연결, 버전 고정과 업데이트.
- [가상 예제](skills/evidence-first/examples/README.md): 원천 충돌·독립 평가·실행 결과 및 선택적 JSON 기록.
- [검증과 테스트 시나리오](tests/README.md): 구조·출처 연결·5×4 독립 조합 검사와 행동 평가.

`information_type` 5종과 `verification_status` 4종은 독립 축입니다. 공식 결정의 존재, 내용의 타당성, 현재 실행 권한을 구분합니다. 설치만으로 항상 적용되는 것은 아니므로, 기본 원칙을 프로젝트 지침에 연결하는 방법도 설치 안내에 포함했습니다.

기존 아키텍처 문서는 `docs/`, 구축 프롬프트는 `prompts/`에 보존되어 있습니다.

### 처음 선택하고 필요할 때 확장

초기 설정에서 **저장 방식**(없음·Wiki·관계형 DB·그래프 DB·조합)과 **활용 기능**(기본 조회·관계 탐색·RAG)을 별도로 선택할 수 있습니다. 공통 행동 원칙은 모든 구성에서 유지됩니다. 이후 저장소와 기능을 추가하거나 기준 저장소를 이전할 수 있습니다.

[설정 및 전환 절차](skills/evidence-first/references/workspace-lifecycle.md)에는 AI의 선택·설정·일상 운영·이전 규칙이 있습니다. 선택적 로컬 보조 도구는 파일 Wiki·SQLite·Oxigraph 그래프 DB를 생성하고 주장 레코드를 실제로 이전합니다. 이전은 읽기 전용 계획 → 복사·전체 값 대조 → 기준 전환으로 진행하며 원본을 남깁니다. 여러 저장소는 기준 하나를 정하고 자동 양방향 동기화를 가정하지 않습니다.

[그래프 DB·RAG 안내](skills/evidence-first/references/graph-and-rag.md)에는 선택 의존성 설치, 객체·출처·모델 관계 조회, 로컬 키워드 RAG 색인·검색·AI의 근거 기반 응답 절차가 있습니다. 그래프 DB는 실제 Oxigraph RDF DB이며 RAG는 Wiki·SQLite·그래프 DB 모두에서 사용할 수 있습니다. 기본 RAG는 로컬 FTS5/BM25 검색이며 원격 모델 API·임베딩 서비스·범용 GraphRAG 추론은 별도 연결 범위입니다.
